# 概述

前端与浏览器底层概念地图：架构解耦、渲染管线开销、框架存在意义、性能四维度，以及虚拟列表 + Content Script 卡顿解法。

# 要点

## 1. 浏览器架构与运行本质

- **JS 引擎（如 V8）：** 解析 JS 与内存管理，无 DOM/BOM
- **宿主环境（Web APIs）：** 注入 `window`、`document`、`fetch` 等
- **JS Binding：** 操作 DOM 经 C++ 桥接调用渲染管线
- **公式：** 前端技术栈 = Host Environment + JS Abstraction + State/UI Sync

## 2. 渲染管线与开销

```text
DOM/CSSOM → Render Tree → Layout → Paint → Composite
```

| 变更类型 | 触发环节 | 开销 | 示例 |
|----------|----------|------|------|
| 几何结构 | Layout→Paint→Composite | 重排极高 | width, height, margin, appendChild |
| 视觉外观 | Paint→Composite | 重绘中等 | color, background-color, visibility |
| GPU 合成 | Composite only | 合成极低 | transform, opacity, will-change |

布局抖动：同一任务中交替读改 DOM 会迫使同步重排。

## 3. 框架底层意义

- Vue/React：Virtual DOM Diff，批量最小化 DOM 操作
- SPA 白屏：空 HTML → 下大 JS → 执行建 DOM → 调 API
- SSR（如 Nuxt）：首屏带内容 HTML + Hydration
- 骨架屏：占位把「推开页面」的重排变成「填充」的重绘，减 CLS

## 4. 性能优化四大维度

1. **路由：** `import()` 代码分割；空闲 Prefetch
2. **依赖：** Tree-Shaking；`manualChunks` 打 Vendor 长期缓存
3. **代码：** 非核心组件懒加载；UI 库按需引入
4. **网络/资源：** WebP/AVIF；预生成 `.gz`/`.br` + `gzip_static`

## 5. 虚拟列表 + 插件高频 DOM

痛点：滚动高频销毁/复用 DOM，Content Script 主线程频繁 fetch 并插节点 → 同步重排与卡顿。

解耦：视口 ID 收集 → Debounce → Background 异步 fetch → `rAF` 批量挂载 → CSS absolute 脱离文档流（`pointer-events: none`）。

## 6. AI 时代工作流

能力 ≈ 业务/架构理解 × 问题拆解粒度 + AI 执行力。建立概念地图；精确拆解任务；维护规则与小模块；自己做边界与性能把关。

# 用法

排查卡顿时先判断是重排/重绘/合成，再按路由 → 依赖 → 组件 → 资源顺序下刀。Chrome 插件场景严格把网络放到 Background，DOM 挂载用 absolute + rAF。
