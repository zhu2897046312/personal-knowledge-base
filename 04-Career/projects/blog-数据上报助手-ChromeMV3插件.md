# 概述

**数据上报助手 · Meta Ads Manager UTM 数据看板**（2026.05 - 至今 · 个人独立设计与开发，从 0 到 1，含一次完整架构重构）

面向跨境电商投放团队的 Chrome 浏览器插件，运行于 Meta（Facebook）Ads Manager 广告后台，解决团队真实订单数据（Shopify/自建订单系统）与 Meta 后台"成效"数据归因口径不一致的问题——在 Ads Manager 原生表格里叠加展示真实订单数、订单金额与自算 ROAS，供运营人员判断广告真实盈利情况。项目最初以油猴（Tampermonkey）脚本验证可行性，后独立打包为 Manifest V3 插件正式交付，历经近 50 个迭代里程碑，中期完成了一次从"无构建单文件脚本"到"WXT + Vue 3 + TypeScript 工程化架构"的完整重写。

# 技术栈

**插件框架**：Chrome Extension Manifest V3 · WXT · Service Worker
**前端**：Vue 3（Composition API）· TypeScript
**网络**：ofetch
**注入机制**：Content Script 多世界注入（Isolated World / MAIN World）· Shadow DOM

# 核心工作与技术亮点

1. **无 API 权限场景下的 DOM 级数据叠加**
   - Meta 未开放官方页面扩展接口，通过 Content Script 逐行扫描 Ads Manager 虚拟滚动表格，动态识别表头列语义、解析 Campaign/Ad set/Ad 三级层级 ID，将真实订单数据以彩色徽标形式精确注入目标单元格坐标，不破坏 Facebook 原生 DOM 结构。
   - 针对 Meta 官方"检测到异常浏览器扩展"反插件弹窗，独立开发 `document_start` 阶段隐身脚本进行拦截消除，保障插件长期稳定可用。

2. **批量接口设计与并发性能优化**
   - 将逐行请求订单数据的 **N 次 GET** 重构为 **⌈N/80⌉ 次批量 POST**（`Promise.all` 并行发起），大幅降低大账户下的网络请求数与主线程阻塞。
   - 设计"占位先显 + 原地更新"展示策略：未命中缓存的行先展示占位值，接口返回后无感刷新，配合增量注入签名机制避免整表重渲染。

3. **时区解析的多级降级链路**
   - Content Script 运行在隔离世界无法拦截页面自身网络请求，在 `MAIN World` 注入独立探针脚本 hook 页面 `fetch`/`XHR`，被动捕获 Meta 内部 GraphQL 响应中的报告时区字段；探针之上叠加 DOM 文案抓取、`storage` 按账户缓存、首次安装静默弹窗兜底等 5 级降级策略，全程不依赖用户手动操作即可解决跨时区账户的日历日期对齐问题。
   - 迭代中修复系统时钟推算与非 UTC 报表时区账户之间的日期偏差 bug，改为直接信任页面日期选择器实际展示文案，避免"今天/昨天"快捷筛选跨账户失效。

4. **用户交互期性能让路机制**
   - 设计并实现"交互感知状态机"：监听指针、键盘、滚轮等事件及弹窗/菜单可见性，用户操作 Facebook 原生控件（自定义列、下拉菜单等）期间插件全表扫描、DOM 监听、订单轮询主动完全让路，空闲后自动恢复，将插件对页面原生交互流畅度的影响降到最低。
   - 针对虚拟滚动场景单独设计轻量"绘制阻塞检测"路径，与重量级交互判断解耦，解决滚动回显被交互窗口误判为忙碌而失效的问题。

5. **存量代码架构重构（约 4700 行单文件 → 模块化工程）**
   - 主导将历史遗留的约 4700 行单体 `content.js` 全量迁移至 WXT + Vue 3 + TypeScript 工程，按"DOM 扫描不改变行为"的严格原则分阶段拆分为 **9 个职责域、40+ 个模块文件**（表格扫描、日期解析、交互状态机、徽标渲染、订单请求等），单函数长度收敛到规范阈值以内（详见 [[WXT 项目文件组织规范]]）。
   - 自建"跨模块类型集成检查"脚手架，对拆分后的依赖注入接口跑类型检查提前发现契约不一致；真机验证阶段定位并修复迁移中误删的兜底扫描逻辑，以及 Chrome 原生 `runtime.onMessage` 异步响应约定（`sendResponse` + `return true`）被误写成 Promise 返回值导致后台消息通道失效的隐蔽问题。
   - 全程保持新旧两套代码树并行、旧树线上不受影响，每个里程碑均产出设计文档与验证记录，保障重构期间业务零感知。

# 量化成果

- 订单接口请求量从 **N 次/页** 降至 **⌈N/80⌉ 次/页**，配合并行请求显著缩短大账户下的数据加载等待时间；
- 表格数据自动刷新间隔从 **约 3 秒/轮优化至约 1.5 秒/轮**，滚动场景下的标签回显延迟从约 0.9 秒降至滚动停止后立即显示；
- 存量代码从 **约 4700 行单体文件** 重构为 **9 个子目录、40+ 个模块文件**（约 6600 行 TS/Vue），显著降低维护与联调成本；
- 独立产出并维护 **50 个迭代里程碑记录**（含背景/实现要点/涉及文件/验证结论）与面向客户的更新说明文档，保障团队协作与交接效率。

# 项目收获

在没有官方扩展接口、只能通过逆向 DOM 结构与被动网络探针获取数据的强约束下，完整走通了"可行性验证（油猴脚本）→ 正式交付（MV3 插件）→ 架构重构（WXT 工程化）"的产品全生命周期，积累了 Chrome 插件多世界脚本通信、复杂状态机设计、大规模存量代码等价重构与真机验证排障的实战经验。
