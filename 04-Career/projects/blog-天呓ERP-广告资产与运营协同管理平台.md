# 概述

**天呓 ERP · 广告资产与运营协同管理平台**（2026.07 - 至今 · 核心成员，独立负责资产管理与运营协同多个业务模块）

面向跨境电商广告投放团队的企业级中后台系统，覆盖广告账户、FB 个号、像素、IP 四类广告资产的登记、查询与批量管理，以及工单处理、运营团队在线状态协同、操作留痕等场景；同时承担将存量遗留系统（内部称 tapeuser）的 Facebook 广告管理页面迁移重构为新架构的工作。

# 技术栈

**前端**：React 19（Composition API）· TypeScript（严格模式）· React Router 7
**UI/状态**：Ant Design 6 · Redux Toolkit + RTK Query · dnd-kit · @tiptap 富文本
**工程化**：Rsbuild · Less + CSS Modules · ESLint + Prettier + Husky + lint-staged + commitlint
**其它**：xlsx（批量导入导出）· dayjs · lodash-es · Cloudflare Pages（wrangler 部署）

# 核心工作与技术亮点

1. **资产管理域四大模块从零搭建**
   - 广告账户、FB 个号、像素管理、IP 登记四个模块均按管理 / 查询 / 我的三种权限入口拆分，统一基于 PageLayout + CommonTable 搭建列表页；广告账户支持批量导入导出、转移运营成员、启停；像素管理对接媒体来源多级筛选与批量导入导出；IP 登记支持快捷粘贴自动拆分 IP/端口/账号密码，减少人工分栏录入。
   - 广告账户、像素等模块的批量导出弹窗补充单次条数上限（5 万条）校验，导入弹窗补充文件类型与大小限制，在前端拦截超限请求。

2. **存量遗留系统迁移重构**
   - 将历史遗留系统中无类型的 Facebook 广告账户列表、主页 / 帖子 / 评论管理、话术中心、UTM 追踪等页面，从 `.jsx` 整体迁移为 TSX + RTK Query 架构，统一接入新增的 `/api-ads` 网关代理；针对该网关下各接口信封格式不统一（部分带 `code`、部分不带）的情况，采用 `envelopeMode: 'full'` 绕开自动解包并在 adapter 层按裸响应自行解析。
   - 迁移过程中定位并修复多个历史遗留 bug，例如主页管理页「主页名称」搜索框因 prop 传递错误从未生效、Antd `Alert` 组件使用已废弃的 `message` 属性产生控制台警告。

3. **工单与运营团队协同域**
   - 落地运营团队成员在线状态机（上线 / 下线 / 请假），请假支持精确到小时的时间选择与工作交接人字段；识别出「我的工单」在线状态请假与运营团队绑定成员请假共用同一个后端接口却各自维护一套结构相同弹窗的重复实现，抽取为可配置的公共组件 `LeaveModal`。
   - 定位多人协同处理工单时，写操作后仅依赖 RTK Query 缓存自动失效会有滞后，改为在关键操作后显式刷新列表 / 详情 / 统计三处数据，保证多人操作时状态及时同步。

4. **跨模块性能与请求治理**
   - 发现广告账户与 FB 个号模块各自重复定义了指向同一个 `/asset/filter/assignable-members` 接口的 RTK Query endpoint，导致资产统计报表页同时挂载三个业务域的浏览 Hook 时并发触发 3 次相同请求；合并为共享 endpoint 并简化下游 adapter，消除重复网络请求与重复的响应校验。

5. **代码规范治理与存量重构**
   - 主导按仓库自定义规范（禁用三目运算符、禁用 TypeScript `enum`、禁止 JSX 模板内联箭头函数、页面模块文件职责拆分）系统性重构存量代码：将糅合筛选 / 分页 / 勾选状态与列定义的页面容器拆分为浏览态 Hook + FilterPanel / Table / BrowseShell 三类展示组件；把 18 个扁平 props 的表格组件收敛为 chrome / data / actions 三组分类 props 并接入 `memo` 浅比较；散落的字符串字面量比较统一收敛为 `as const` 常量对象取值（详见 [[TypeScript 表达式复杂度与常量枚举规范]]）。

6. **全站基础能力**
   - 登录后主布局新增全站水印，复用已有的 `getCurrentUser` 用户信息缓存拼接 `displayName-id` 作为水印内容，业务页面无需任何改动即可生效。

# 量化成果

- 约 4 周内产出 **144 个**非合并提交，净变更约 **+37,500 / -20,300** 行代码，累计涉及 **800+** 次文件改动；
- 独立搭建或重构 **7 个**核心业务模块：广告账户、FB 个号、像素管理、IP 登记、工单管理、操作日志、资产统计报表；
- 为 **5 个**资产列表页（广告账户、FB 个号、IP 登记、像素、店铺）统一接入批量导入 / 导出能力；
- 消除 1 处跨业务域重复查询 endpoint，将资产统计报表页的并发相同请求数从 **3 次降至 1 次**；
- 代码规范治理类提交（`refactor`/`style`/`docs`）合计 **40+ 次**，推动禁三目、禁 enum、消除模板内联箭头函数等规范在存量模块落地。

# 项目收获

在真实企业级中后台项目中完整实践了「新模块从 0 到 1 搭建 → 存量遗留系统迁移 → 跨模块性能与请求治理 → 规范化重构」的全链路工作，积累了大型 RTK Query 项目中请求去重与缓存失效策略的实战判断力，以及跨页面复用组件抽取（`LeaveModal`、`FilterPanel` 等）与严格编码规范在存量代码上落地推行的能力。
