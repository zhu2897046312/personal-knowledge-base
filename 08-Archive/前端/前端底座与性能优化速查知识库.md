# 🚀 前端底座与性能优化速查知识库

## 1. 浏览器架构与运行本质

### 核心解耦模型

* **JS 引擎 (如 V8)：** 只负责解析 JS 语法与内存管理（堆/栈），**没有任何 DOM/BOM 概念**。
* **宿主环境 (Web APIs)：** 浏览器（C++）注入 `window`、`document`、`fetch` 等对象。
* **JS Binding：** JS 操作 DOM 本质是**通过 C++ 暴露的桥梁去调用浏览器的底层渲染管线**。
* **统一公式：**

$$\text{前端技术栈} = \text{Host Environment (宿主环境)} + \text{JS Abstraction (封装层)} + \text{State/UI Sync (状态同步)}$$



---

## 2. 浏览器渲染管线与开销分类

### 渲染流水线 (Rendering Pipeline)

$$\text{[DOM/CSSOM]} \longrightarrow \text{[Render Tree]} \longrightarrow \text{[Layout (重排)]} \longrightarrow \text{[Paint (重绘)]} \longrightarrow \text{[Composite (合成)]}$$

| 变更类型 | 触发环节 | 开销等级 | 触发属性示例 |
| --- | --- | --- | --- |
| **几何结构变更** | Layout $\rightarrow$ Paint $\rightarrow$ Composite | 🔴 **重排 (Reflow) - 极高** | `width`, `height`, `margin`, `appendChild` |
| **视觉外观变更** | Paint $\rightarrow$ Composite | 🟡 **重绘 (Repaint) - 中等** | `color`, `background-color`, `visibility` |
| **GPU 合成变更** | Composite Only | 🟢 **合成 (Composite) - 极低** | `transform`, `opacity`, `will-change` |

> ⚠️ **布局抖动 (Layout Thrashing)：** 在同一个任务中“交替读取与修改 DOM”会迫使浏览器清空队列，触发同步重排，严重卡顿。

## 3. 框架底层存在的意义

* **Vue / React (视图层)：** 通过 **Virtual DOM** 在纯 JS 内存中进行 Diff 计算，将多次频繁变化合并为**最小化的批量 DOM 操作**，减少重排。
* **SPA 白屏根源：** `空 HTML` $\rightarrow$ `下载大 JS` $\rightarrow$ `执行生成 DOM` $\rightarrow$ `调 API 填数据`（等待链路长）。
* **SPA 演进解法：**
* **SSR (如 Nuxt)：** 服务端拼接好带内容的 HTML 返回，实现**首屏零白屏**，后续下载 JS 进行**水合 (Hydration)** 接管交互。
* **骨架屏 (Skeleton)：** 用 CSS 提前占位，将“推开页面”的重排转化为“填充内容”的重绘，避开 CLS（布局偏移）。

## 4. 性能优化四大维度

### ① 路由维度 (Routing)

* **路由懒加载：** 基于 `import()` 实现**代码分割 (Code Splitting)**，打包工具会将页面拆为独立 Chunk。
* **智能预加载 (Prefetch)：** 利用 `requestIdleCallback` 在浏览器空闲时偷偷下载视口内链接对应的 JS（如 `<NuxtLink>`）。

### ② 依赖维度 (Dependencies)

* **Tree-Shaking：** 打包时自动剔除未使用的导出代码（需支持 ES Module，如 `lodash-es`）。
* **手动拆包 (`manualChunks`)：** 将不变的大型第三方库（如 Element Plus）单独打成 Vendor 包，利用 **HTTP 长期强缓存**。

### ③ 代码维度 (Code/Components)

* **首屏非核心组件懒加载：** 视口外的重度组件（如评论区、代码高亮）使用懒加载（如 Nuxt `Lazy` 前缀组件）。
* **按需引入：** 配合 `unplugin-vue-components` 等工具按需加载 UI 库的 JS/CSS。

### ④ 网络/资源维度 (Assets & Network)

* **图片格式优化：** PNG/JPEG 转 **WebP / AVIF**，体积通常压缩 **25%~80%**。
* **文本预压缩：** 打包生成 `.gz` 或 `.br`，配合 Nginx `gzip_static on;` 省去服务器实时压缩开销。

## 5. 虚拟列表与 Chrome 插件高频 DOM 渲染卡顿方案

### 核心痛点

虚拟列表滚动时会高频销毁/复用 DOM 节点，若 Content Script 在主线程频繁 `fetch` 并直接操作 DOM 插入节点，会引发**高频同步重排**和**滑动卡顿**。

### 标准架构解耦方案

```
[页面滚动 / 虚拟列表更新]
       │
       ▼ (仅收集视口内 ID，不触碰 DOM)
[防抖节流队列 (Debounce ~250ms)]
       │
       ▼ (发送消息发给 Background)
[Background Service Worker] ──> [异步 Fetch/Post 请求 & 数据对比]
       │
       ▼ (返回需要打气泡的匹配数据)
[requestAnimationFrame 批量挂载] ──> [CSS absolute 独立定位 (不触发重排)]

```

* **绝对定位隔离：** 挂载的气泡使用 `position: absolute; pointer-events: none;`，使其脱离文档流，不挤压原广告节点。
