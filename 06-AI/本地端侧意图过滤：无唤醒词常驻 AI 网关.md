# 目标

记录"设备不设唤醒词、本地通电常驻监听"这个想法要如何落地：核心难点是怎么把日常闲聊/杂音和真正的控制指令区分开，以及为什么本地端侧小模型前置过滤是目前公认的最优解。这条思路是 [[LLM Tool Calling 落地：CLI 与配置化 Agent]] 的延伸——把"云端大脑"往本地又推进了一层。

# 知识点

## 1. 全时监听下，如何区分"命令"与"杂音/闲聊"

取消唤醒词、常驻开麦从技术上完全可行，行业内通常组合以下 4 种技术来过滤：

1. **语义意图阈值与 Tool 匹配**：STT 转出文字后先过一层意图识别与置信度打分，只有命中某个 Tool Schema（如 `control_ac`）才会真正触发硬件动作，日常闲聊没有匹配到任何 Tool 就静默忽略。
2. **声纹识别与声源定位**：多麦克风阵列做 Beamforming 计算声音来源方向，过滤电视/他人方向的声音；声纹锁只响应绑定过的主人声音。
3. **视听融合**：设备摄像头/红外传感器判断你的脸/眼神是否朝向它，只有对着它说话才响应，对着旁边人说话则忽略（苹果 Vision Pro、带摄像头的桌面机器人常用此思路）。
4. **本地端侧轻量小模型前置过滤（核心手段）**：本地先跑 VAD（语音活动检测）过滤掉非人声，再用一个极小的本地 NLP/意图分类模型判断"这句话是不是设备控制命令"——是才推送云端大模型，只是闲聊直接本地丢弃。

## 2. 为什么商业产品（小爱、Siri）依然坚持要唤醒词

| 维度 | 无唤醒词（常驻全时监听） | 有唤醒词 |
| --- | --- | --- |
| 隐私安全 | 24 小时录音并上传云端，极易引发隐私焦虑 | 唤醒词本地离线计算，不唤醒不上传，用户更安心 |
| API 费用与带宽 | 24 小时 STT+LLM 推理，Token 账单和流量呈几十倍暴涨 | 只有触发后几秒消耗 Token，成本极低 |
| 误触率 | 意图识别再准，看电影/打游戏的台词仍可能偶尔误判触发 | 误触率极低，指令执行确定性高 |

大厂不主推常驻监听并非想不到，而是商业化的现实阻碍：**隐私公关风险**（24 小时默默监听会被解读为"偷听用户"）和**硬件成本矛盾**（要在端侧跑小模型做常驻过滤，需要带 0.5~2 TOPS 算力 NPU 的芯片，成本从几十元飙到 200~500 元，消费者很难为"省一句唤醒词"多付这笔钱）。

## 3. 终极方案：ESP32-S3-BOX / 小智 AI（Xiaozhi AI）+ 端侧 SLM 意图网关

把本地常驻硬件设计成一个"智能网关/阀门"：

```text
【本地硬件（如 RK3588 / 树莓派 5 / 高算力 ESP32）】              【云端 / 远程 Go Server】
1. 24 小时常驻监听（麦克风）
2. 本地小模型 / 离线 STT 实时转文字
3. 本地轻量意图分类器（端侧 SLM）判断：是不是家电控制指令？
        │
   ┌────┴────┐
是控制指令    是闲聊/杂音
   │            │
   ▼            ▼
封装发送给     本地直接丢弃
远程 Go/Eino   （Token 消耗 0，带宽消耗 0）
触发云端 LLM Tool Calling
```

带来的三个收益：

- **Token 费用暴降 99%**：全部实时上云一天可能上百元 Token 费；加本地过滤后一天真正触发云端的可能只有几十句话，成本降到几分钱。
- **反应速度极快**：简单开关命令（"关灯"）本地小模型匹配到本地词库/正则后可以直接在本地发 MQTT/红外指令，响应控制在 100ms 内，比传统语音音箱还快。
- **隐私屏障**：日常对话、电视声音只在本地芯片 RAM 里处理，非控制指令的数据根本不出路由器。

### 开源落地选型

- **树莓派 5 / RK3588 + Ollama**：本地跑 Qwen2.5-0.5B/1.5B-Instruct 做二分类"这句话是不是控制家电"，是才转发给云端 DeepSeek 做真正的复杂推理。
- **ESP32-S3 + `esp-sr`**：乐鑫官方开源语音识别库，可在十几块钱的双麦克风阵列板上本地离线识别数百条常见意图，不支持复杂泛化，但作为无唤醒词前置过滤足够省电廉价。
- **小智 AI（Xiaozhi AI）/ ESP32-BOX**：GitHub 上数万 Star 的现象级开源项目，基于 ESP32-S3 等百元级硬件，本地端侧 VAD + 离线意图识别配合云端大模型和 MQTT 通信，做成带屏幕的桌面摆件，支持免唤醒连续对话和动态 Tool Calling 控家电。

### 折中的"隐式唤醒"方案

如果不想做全套端侧 SLM，也可以用更轻的"隐式唤醒"代替喊出唤醒词：

- **"看我即唤醒"**：加装红外毫米波雷达或摄像头，只有检测到人走近 1 米范围/面朝设备时才开启 10 秒免唤醒监听。
- **"结合设备状态"**：把环境传感器数据（如室温 31℃ 且空调关着）作为上下文喂给大模型，用户只需说"好热啊"，系统结合状态就能高置信度直接执行，不需要明确唤醒词。

## 4. 市面上已有的同类实现

不是没人做，而是这正是 2024~2026 年 AI 硬件圈最火的赛道之一，只是大厂顾虑商业化风险而没有主推：

- **小智 AI / ESP32-BOX**：见上文，开源社区现象级项目。
- **Home Assistant Green / Yellow**：本地常驻运行控制中枢，用本地 Whisper/Piper 引擎做端侧语音识别与意图过滤，彻底丢弃云端依赖，局域网内免唤醒控制。
- **Rabbit R1 / Humane AI Pin**：独立 AI 硬件，设备常驻（或按键/眼球激活），本地只做极轻量音频编码与前置过滤，核心意图理解交给云端 LAM（Large Action Model）执行。
- **高端车载语音（理想、蔚来等）**：车内多麦克风阵列做声源定位（只监听主驾）+ 局域网端侧 NPU 实时做意图分类，分类成功才触发空调等控制，实现"区域免唤醒"。

# 总结

> 无唤醒词常驻监听在技术上完全可行，核心是把大模型（或端侧小模型）当成"意图过滤器"——只响应能精准匹配 Tool Calling 强类型指令的句子，忽略所有日常闲聊，从而同时解决 Token 成本暴涨和隐私焦虑两大痛点。终极架构：`本地高算力硬件（常驻监听 + 本地 SLM 意图过滤）→ 远程 Go/Eino 服务（动态 Tool 路由 + 强类型校验）→ 云端大模型（复杂推理）/ 本地 MQTT（硬件执行）`。大厂受限于隐私公关风险和硬件成本没有主推，但开源社区（小智 AI）和新锐 AI 硬件公司已经把这条路走通，个人开发者做这个方向反而有很大发挥空间。
