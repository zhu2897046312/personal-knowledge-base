# 概述

**电商数据自动化系统**（2025.07 - 2025.11 · 个人独立设计与开发）

面向跨境电商运营团队的数据自动化采集与入库平台，解决人工登录速卖通/菜鸟/店小秘等多个电商与物流后台逐一导出库存、出入库流水、销量报表并手工整理入库的重复劳动问题。通过 Selenium 模拟登录与页面操作自动下载各平台 Excel 报表，再统一清洗、字段映射后批量写入 MySQL，供后续经营分析使用；同期独立产出一款可循环合并的 Excel 表格工具，服务非技术人员的数据整理需求。

# 技术栈

**自动化**：Python · Selenium WebDriver · Chrome 持久化用户态
**数据处理**：pandas · openpyxl · xlrd
**存储**：MySQL · SQLAlchemy ORM · PyMySQL
**配置与调度**：YAML 配置化多店铺管理 · Shell 一键启动脚本 · 按日期分类日志

# 核心工作与技术亮点

1. **多平台无 API 场景下的浏览器自动化采集**
   - 针对速卖通（POP/全托两种店铺形态）、菜鸟库存管理、店小秘本地库存等无开放接口的后台，用 Selenium 驱动 Chrome 持久化用户目录登录态，自动识别登录页并回填账号密码，覆盖库存、出入库流水、每日销量、销量列表等 5+ 类报表的自动导出。
   - 封装通用的下载完成检测（轮询 `.crdownload` 临时文件 + 定位下载进度条元素）与文件重命名归档逻辑，统一处理不同报表页面的下载时序差异。

2. **在途库存明细的批量分组采集**
   - 从菜鸟库存 Excel 中提取全量货品 ID 落盘为文本文件，再按 **5 个 ID 一组** 分批在库存明细页发起查询-导出，规避页面对大批量搜索的性能与稳定性限制。
   - 实现跨 iframe/frame 的递归元素查找（`find_element_in_all_frames_verbose`），解决菜鸟后台页面深层内嵌 frame 导致的元素定位失败问题；支持命令行直接传入货品 ID 列表或文本文件两种输入方式。

3. **多来源出入库流水的统一入库**
   - 出入库流水存在"菜鸟系统进销存实时出入库"与"店小秘发货 order_1"两种结构完全不同的数据来源，通过 sheet 名称分流解析、列名映射与业务类型映射字典（销售出库/调拨入库/盘盈盘亏等）统一归一化后写入同一张 `warehouse_flow` 表。
   - 全链路以字符串类型读取 Excel 数值列，仅对库存变动数、余额等确需数值运算的字段做安全类型转换，避免长货品 ID、物流单号被自动转换为科学计数法造成精度丢失。

4. **配置化多店铺管理与一键启动**
   - 通过 `config.yaml` 集中管理各店铺账号、Chrome 用户数据目录、下载目录等参数，新增店铺无需改动脚本代码；`run_all.sh`/`export_all.sh` 一键串联全部采集与入库脚本，按日期自动分类存放日志与下载文件。

5. **面向非技术人员的 Excel 合并工具**
   - 独立开发命令行 Excel 合并工具，自动识别多个文件中表头完全一致的 sheet 进行合并，合并前移除辅助的"来源文件"列做标准化比较，使已合并文件可以继续参与下一轮合并，形成增量归档能力。
   - 全部数据以字符串形式读写，避免长数字被 Excel 转换为科学计数法；配套撰写面向非开发人员的中文使用手册与常见问题排查说明，降低团队使用门槛。

# 量化成果

- 历时约 4 个月（2025.07 - 2025.11）独立完成 **80 次迭代提交**，覆盖 4+ 电商/物流平台的数据采集与入库全链路；
- 单次在途库存明细采集从"手动查询"改为 **5 个货品 ID/组** 的自动化批量导出，支撑近千个货品 ID 的全量采集；
- 出入库流水导入统一支持 2 种异构数据源（菜鸟/店小秘），消除人工按来源分别整理的重复工作；
- Excel 合并工具支持文件夹级批量合并与已合并文件的循环合并，配套中文手册使非技术同事可独立完成日常数据整理。

# 项目收获

在没有官方接口、只能依赖浏览器自动化对接多个第三方电商后台的约束下，完整积累了 Selenium 深层 iframe 定位、下载时序检测、异构数据源统一入库等实战经验；同时通过配置化与文档化设计，把一次性脚本沉淀为团队可长期复用、非开发人员也能上手的自动化工具链。
