# 概述

**天呓网络科技有限公司 · 前端工程师**（2026.05 - 至今，约，请核实起始月）

五线并行：独立设计开发 Chrome MV3 插件「数据上报助手」，作为核心成员参与「天呓 ERP」企业级中后台系统开发并独立承接其中 Snapchat 广告投放前端模块，独立设计开发自研广告投放后端服务「svr_ads」的 Snapchat 渠道后端（Go + Gin + GORM + Redis + asynq），实现该渠道前后端全栈交付，参与跨境电商 Shopify 主题「Shrine Theme Pro」的二次开发，同时主导开发 Python 后端服务「SaaS 店铺商品采集系统」，技术方向覆盖浏览器插件、企业级中后台、广告开放平台全栈集成、Shopify 主题二次开发与后端数据采集服务。

# 主要工作内容与成果

**数据上报助手（Chrome MV3 插件）**（详见 [[blog-数据上报助手-ChromeMV3插件]]）：

- 逆向解析 Meta Ads Manager 虚拟滚动表格 DOM 结构，实现无官方接口下的数据精准叠加，开发隐身脚本拦截平台反插件检测弹窗
- 设计批量订单接口与并行请求架构，将逐行 GET 重构为分片并行 POST，构建 5 级时区降级解析链路实现跨时区账户日期自动对齐
- 主导将约 4700 行单体 `content.js` 重构为 WXT + Vue 3 + TypeScript 模块化工程（9 个职责域、40+ 模块）

**天呓 ERP · 广告资产与运营协同管理平台**（React 19 + TypeScript + Redux Toolkit / RTK Query，详见 [[blog-天呓ERP-广告资产与运营协同管理平台]]）：

- 独立搭建广告账户、FB 个号、像素管理、IP 登记四大资产模块
- 主导存量遗留系统从无类型 JSX 迁移为 TypeScript + RTK Query 架构，统一接入新网关并修复多个历史遗留 bug
- 落地运营团队在线状态协同机制（上线/下线/请假），抽取跨页面复用组件消除重复实现
- 发现并合并跨业务域重复定义的查询 endpoint，主导仓库编码规范治理（禁三目、禁 enum、组件职责拆分）

**Snapchat 广告投放全栈模块**（前端「天呓 ERP」内新增 + 自研后端服务「svr_ads」，详见 [[blog-天呓ERP-广告资产与运营协同管理平台]]、[[blog-Snapchat 广告投放后端服务「svr_ads」]]）：

- 独立设计并实现 Snapchat 渠道前端（账号管理/广告发布/模板管理三个子模块）与后端服务「svr_ads」的 Snapchat 渠道模块（Go + Gin + GORM + Redis + asynq），实现该广告渠道端到端全栈交付
- 后端：封装 Marketing/Business/Ad Library 三大 API 组 SDK 并归一化响应信封，基于 asynq 设计六阶段异步发布引擎，解决消息重投场景下的幂等落库与阶段推进一致性问题，落地 OAuth 分布式并发刷新与 Redis 令牌桶限流降级
- 前端：OAuth 弹窗授权（仅校验消息来源而非硬编码回调域名）、三层级联发布列表下钻导航、超大素材矩阵虚拟列表与批量素材保位分配算法均为独立设计实现

**跨境电商 Shopify 主题「Shrine Theme Pro」**（基于 Dawn 二次开发，详见 [[blog-跨境电商 Shopify 主题「Shrine Theme Pro」]]）：

- 扩展 7 个购物车侧转化 App Block（倒计时锁单、阶梯满减/包邮进度条、条件赠品、购物车内追加销售等），条件规则引擎最多支持 6 种触发方式
- 落地捆绑套装促销、定价方案对比表、品牌故事时间轴等营销型 Section，及独立站营销落地页模板系列
- 搭建 26 种语言的国际化资源与 RTL 布局开关，覆盖礼品卡兑换页与完整客户账户体系模板

**SaaS 店铺商品采集系统**（Python + FastAPI 后端服务，详见 [[blog-SaaS 店铺商品采集系统-多平台采集与 Shopify CSV 导入]]）：

- 主导设计多平台商品采集架构：域名/页面特征自动识别 12 个专属适配器平台，未命中平台统一走通用兜底解析链，不因平台不在列表直接拒绝采集
- 攻坚无官方接口/强反爬平台：1688 从 HTML 抓取切换为官方开放平台接口规避滑块验证，TikTok Shop 用 Node.js + Playwright 渲染真实 Chrome 页面绕过前端空壳
- 设计代理池评分机制与数据库持久化方案，解决服务重启后代理健康状态清零问题；梳理类目/库存/销量等歧义字段的多源优先级取值，建立"宁可留空不猜测"的数据治理原则
