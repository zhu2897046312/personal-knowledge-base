# 概述

**医美品牌「傲莱菈」产品验真 H5 与公众号运营后台**（广东真格软件有限公司实习期间参与）

面向医美机构的产品验真业务：消费者通过扫码或输入序列号在 H5 完成假体等产品的序列号验真与质保卡查询，与微信公众号「ANGELA PEACH · 傲莱菈」场景配合使用；合作机构与运营团队通过独立管理后台维护序列号、机构与质保卡主数据。项目拆成 H5 客户端与运营后台两个独立前端工程，共用同一套后端接口。

# 技术栈

- **H5 客户端**：Vue 3 · TypeScript · Vue Router 4 · Vite 6 · Vant 3 · Tailwind CSS 4 · Axios · 条码识别（`@zxing/library`、`quagga`）· 微信 JS-SDK
- **运营后台**：Vue 3 · TypeScript · Vue Router 4（Hash 路由）· Vite 5 · Ant Design Vue 4 · Pinia · Sass · Tailwind CSS 3 · wangEditor / Quill 富文本 · ECharts · Cropper.js · xlsx 导入导出

# 核心工作与技术亮点

1. **移动端验真入口与微信场景适配**
   - 首页支持扫码与手动输入序列号两种查询路径，接入 `@zxing/library`/`quagga` 做条码识别；集成微信 JS-SDK 配置（如 `initWxConfig`），适配公众号内打开、分享等典型移动端场景。

2. **机构端 / 用户端双动线设计**
   - `/organ/*` 机构端覆盖登录鉴权（未登录路由守卫拦截）、质保卡列表、新增录入（含手术日期、图片凭证上传等表单项）、详情与个人中心；`/user/*` 用户端覆盖质保卡查询与手机号绑定，两条动线共用底层接口但权限与展示逻辑独立维护。

3. **运营后台 RBAC 与主数据管理**
   - 落地部门、角色、管理员、权限、数据字典等基础能力，支撑序列号、合作机构、质保卡三类主数据的多角色分工维护；质保卡模块支持 Excel 批量导入，降低运营录入成本。
   - 集成 wangEditor / Quill 富文本、ECharts 图表、Cropper.js 裁剪上传等中后台高频能力，仪表盘做了移动端布局适配判断。

4. **前后端分离下的双端接口对齐**
   - H5 与运营后台均通过 Axios 调用同一套后端 REST 接口，字段与状态码以后端约定为准；两端职责边界清晰（H5 侧重 C/B 端验真动线体验，后台侧重主数据与审核效率），降低了双端并行开发时的协调成本。

# 量化成果

- 交付 **2** 个独立前端工程（H5 客户端 + 运营后台），共用同一套后端接口；
- H5 覆盖 **3** 大功能域：首页验真、机构端（`/organ/*`）、用户端（`/user/*`）；
- 运营后台覆盖记录管理（序列号 / 机构 / 质保卡三类主数据）与系统管理两大能力域，RBAC 基础配置覆盖部门、角色、管理员、权限、数据字典 **5** 类。

# 项目收获

- 在真实医美行业的验真 + 质保场景下，完整实践了移动端条码识别、微信生态适配与中后台 RBAC 体系的组合落地。
- 体会到"同一套后端接口、两个独立前端工程"分工模式下，接口契约先行约定的重要性——H5 与后台各自迭代时，字段/状态码的一致性直接决定联调效率。
- 积累了 Ant Design Vue 中后台里富文本、图表、文件裁剪上传等常见能力组件的拼装经验，以及移动端 H5 结合 Vant 快速交付一致体验的方法。
